This is extremely useful for the agent.


For example:


That means tomorrow, next week, etc. automatically stay correct.

# 18. The filter data model

Don't build separate date logic for every module.

Create one universal structure.

Conceptually:

```ts
type DateFilter = {
  field: string
  operator:
    | "on"
    | "before"
    | "after"
    | "between"
    | "relative"

  value?: string
  from?: string
  to?: string
}
```

Examples:

```ts
{
  field: "dueDate",
  operator: "relative",
  value: "this_month"
}
```

or:

```ts
{
  field: "createdAt",
  operator: "between",
  from: "2026-08-01",
  to: "2026-08-26"
}
```

## The important part

I would make the **Date Engine itself a platform-level component**, alongside Search and Filters.

So your architecture becomes:

```text
Universal Search
       +
Universal Filters
       +
Universal Date Engine
       +
Universal Sort
       +
Universal Group
       +
Saved Views
       +
AI Query Parser
```

Then **every module uses the same behavior**.

That gives you things like:

> Tasks → Due Date → August 2026 → High Priority → GB Banquet

and:

> Finance → Transaction Date → August 2026 → Business Expense

and:

> Email → Received → Last 7 Days → Client → Needs Reply

all using the same underlying filter architecture.
