Yes. I understand the purpose of the **`/studio/inbox`** now.

This Inbox should **not be a normal inbox**, and it should not simply show every incoming email/message/file.

It should become the **primary intelligence ingestion layer for Personal OS**.

Its job is:

> **Continuously receive raw information → identify what matters → extract it → classify it → connect it to the Personal OS → preserve the original source → trigger the appropriate agents.**

And because this is where bank statements, investment information, invoices, client requests, documents, receipts, subscriptions, etc. may enter, the Inbox needs to be treated almost like an **event/data ingestion system**, not just a UI feature.

---

# 1. Core purpose of `/studio/inbox`

The Inbox should answer:

> **"What information has entered my digital life that Personal OS should know about?"**

It should automatically process:

* Emails
* Email attachments
* PDFs
* Images
* Screenshots
* Documents
* Statements
* Receipts
* Invoices
* Investment documents
* Insurance documents
* Tax documents
* Client requests
* Project briefs
* Calendar-related messages
* Subscription emails
* Payment notifications
* Important personal documents
* Financial documents
* URLs
* Other captured information

But it should **not turn everything into a task**.

That distinction is extremely important.

# 5. Importance detection

This should be one of the most important components.

Every incoming item gets an:

```text
importance_score
```

and:

```text
importance_level
```

For example:

```text
Critical
Important
Relevant
Low Value
Noise
```

The Inbox should primarily surface:

### Critical

Things that could cause immediate consequences.

Examples:

* bank statement
* payment failure
* security alert
* tax notice
* investment transaction
* account warning
* deadline
* important client request

### Important

Things that need to be known or acted on.

Examples:

* project request
* invoice
* subscription renewal
* new client requirement
* investment statement
* contract
* approval request

### Relevant

Useful information that doesn't require immediate action.

### Noise

Marketing emails, generic notifications, irrelevant newsletters, etc.

The system can retain them if required, but they should not pollute the Personal OS.

# 47. Inbox intelligence should be confidence × impact

A mistake in:

> "This is a social media email."

> "This ₹25,000 transaction belongs to Business."

```text
confidence
×
action impact

```

Not just AI confidence.

### The most important conceptual change

Your `/studio/inbox` should be treated as **the Personal OS's ingestion and intelligence gateway**, not merely a page where you view messages.

It should know:

**What arrived → whether it matters → what it contains → how sensitive it is → what entities it belongs to → what domain owns the extracted information → what action is necessary → what source proves it → which agent should process it next.**

That architecture is what will let you eventually receive a **bank statement, investment statement, client request, invoice, receipt, contract, subscription notification, or random screenshot** and have the rest of Personal OS update itself without you manually entering everything.
