You give the Assistant the raw sources, and it performs the organization.

# 9. Source precedence rules

You can define rules such as:

```text

>
Explicit client instruction
>
Current project record
>

>
```

But don't hard-code one universal rule for every entity.

For example:

### Financial amount

Original statement / invoice should outrank an email summary.

### Brand name

Existing verified client record should outrank an ambiguous document mention.

# 16. It should detect removed work too

Previous:

```text
Restaurant B
2 Reels
```

Current:

```text
Restaurant B
1 Reel
```

Assistant:

> This week's requirement changed from 2 reels to 1.

Then it updates the **current occurrence**, not necessarily the permanent recurring commitment.

That distinction is very important:

```text
Permanent Commitment:
2 reels/week

Current Week Exception:
1 reel
```

You don't want one unusual week to permanently alter the contract/commitment.

# 18. It should create tasks intelligently

A row doesn't always equal a task.

For example:

```text
WOW Indian
Weekly Content
3
```

could represent a commitment, not three tasks.

Whereas:

```text
Create Reel 1
Create Reel 2
Create Reel 3
```

clearly represents individual tasks.

The Assistant needs to infer the **semantic structure**, not just import spreadsheet rows mechanically.

---

# 19. It should ask only when necessary

Good:

> I found 12 deliverables and matched them to existing projects. One brand, "Restaurant C", doesn't exist yet. Should I create it under Karna Kreative?

Bad:

> What's the client?
> What's the project?
> What's the priority?
> What's the deadline?
> What's the task type?

when all of that is already in the sources.

The entire purpose of this system is to avoid those questions.
