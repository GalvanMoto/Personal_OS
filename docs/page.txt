# 9. The most important interaction pattern

Don't make users constantly navigate.

For example:

**Today → click task**

opens:

> Task Drawer

Then:

**click "Start Task"**

opens:

> Task Workspace

Then:

**click "Find assets"**

opens:

> Context Drawer / Search

Then:

**click logo**

opens:

> File Preview

The user stays in the same workflow.

That is much better than:

`Dashboard → Tasks → Project → Files → Drive → Document → Back → Back → Task`

---

# 10. Final UI count I'd use

For the first serious version:

```text
18 Main Pages
8 Core Modules
7 Global Drawers
12 Major Modals
11 Sidebar Navigation Items
5 Full-screen Workflows
```

But **don't interpret that as 53 different screens the user must navigate through**.

The actual experience should feel like:

> **1 dashboard + 1 inbox + 1 assistant + contextual drawers**

with everything else appearing when needed.

For your use case, that is the sweet spot between **powerful** and **overwhelming**.
